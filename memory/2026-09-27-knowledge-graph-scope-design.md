# 知识图谱挂载范围设计

## 结论

知识图谱应以知识库/课程为主范围，不应以单个文件作为最终图谱。文件级思维导图可以继续作为自动抽取和来源证据，但题目、知识点关系和学生复习推荐应最终落到知识库级的规范化知识点上。

## 当前系统约束

- `document_generation` 当前按文档保存 `mindmap`、`flashcards` 和 `quiz`。
- 题目使用 `knowledge_point_ids` 关联文档自己的思维导图节点。
- `KnowledgePointMastery` 当前按 `student_id + doc_id + node_id` 记录掌握度。
- 系统已经存在知识库级知识图谱展示接口，但它来自检索索引，不适合作为题目关系的唯一事实来源。

## 推荐方案：知识库规范图谱 + 文件来源映射

1. 每个课程知识库维护一套规范化知识点和知识点关系。
2. 上传或解析文件时，先生成文件级候选知识点，再匹配到知识库已有节点；无法匹配的由教师确认后新增。
3. 每道题可以关联一个主知识点和多个次要知识点，同时保留题目来源文档和原始章节。
4. 学生错题和掌握度按规范化知识点聚合，复习时从薄弱知识点、前置知识点和相邻知识点中选题。

建议的核心关系类型：`part_of`、`prerequisite`、`related_to`。不要把所有关系都简化为“相关”。

## 为什么不是文件级最终图谱

- 同一个知识点会在 ch1、ch2 和综合试卷中重复生成，学生掌握度无法跨文件合并。
- 题目只能跟随某个文件的节点，无法从多个课件抽取同一知识点的题目进行复习。
- 文件重命名、重新生成思维导图或导入综合试卷时，节点 ID 容易失效。

## 数据层建议

- `knowledge_graph_node`：`kb_id`、规范节点 ID、名称、层级、状态。
- `knowledge_graph_edge`：起点、终点、关系类型、权重和来源。
- `document_knowledge_node`：文档到规范知识点的映射，保留章节/页码和置信度。
- `question_knowledge_node`：题目到规范知识点的映射，支持主次知识点和权重。
- 学生掌握度逐步从文档局部节点迁移到 `student_id + kb_id + node_id`，同时保留 `doc_id` 作为来源维度。

题目当前存放在 JSON 中，第一阶段可用 `(doc_id, generation_id, question_id)` 作为稳定题目引用；题目规模扩大后再拆成独立题目表。

## 三种实现路径

### A. 继续使用文件级思维导图

最小改动，适合快速演示；但跨课件复习和掌握度合并会持续失真，不建议作为正式方案。

### B. 知识库规范图谱 + 文件映射

改动适中，能复用当前文档思维导图、题目 `knowledge_point_ids` 和个性化出题逻辑，适合当前系统。推荐采用。

### C. 独立图数据库和课程级知识平台

长期能力最强，但需要引入图数据库、同步机制、权限和版本管理，当前阶段投入过大。

## 额外边界

一个知识库最好只对应一门课程或一个明确的课程版本。不要把 C++、数据库和离散数学混在同一套规范图谱中。若同一课程有多个版本，应增加课程/版本命名空间，而不是复制一批无法关联的文件级节点。

## 推荐

采用 B：知识库承载规范图谱，文件承载来源和局部抽取结果，题目挂到规范知识点。第一期先做知识点管理、文件映射、题目映射和按薄弱知识点推题，不先引入独立图数据库。
