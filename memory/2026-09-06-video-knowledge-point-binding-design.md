# Design: 视频挂载到课件思维导图知识点

Generated by office-hours on 2026-09-06  
Status: APPROVED  
Mode: Startup（校内项目，尽快稳定上线）

## Problem Statement

当前 PPT/PDF 课件和视频都以独立 `document` 的形式平铺在知识库中。视频通常只是某个课件知识点的补充学习材料，但学生无法从思维导图知识点直接找到对应视频，资料列表也会随着视频增多变得杂乱。

目标是让老师把已经上传的视频直接挂载到某份课件思维导图的某个知识点，学生点击该知识点即可看到并播放视频。同时必须保留视频原有 `document.id`、MinIO 对象以及已经产生的学生观看记录。

## Demand Evidence

- 项目将用于校内教学，需要尽快稳定上线。
- 系统已经产生真实的学生视频观看记录。
- 明确要求历史视频不能重新上传，只能直接挂载。
- 当前需求来自产品设计判断：知识库按知识点组织后更有条理，学生学习路径更轻松。
- 尚未通过真实学生观察验证“学生会主动点击思维导图寻找视频”，因此第一版必须可回退，并保留未归类视频入口。

## Status Quo

- 视频和课件都存放在 `document` 表中，并位于同一知识库层级。
- 视频上传后直接进入完成状态，不参与 PPT/PDF 的解析和 AI 内容生成。
- 学生从统一的资料下拉列表选择视频，然后在课件面板内播放。
- 学生观看状态保存在 `student_video_progress`，通过 `student_id + video_doc_id` 唯一定位。
- 思维导图存储在 `document_generation` 的 `mindmap` JSON 中，节点由稳定的 `node_id` 标识。
- 当前思维导图节点只支持展开和折叠，没有知识点详情或视频入口。

## Target User & Narrowest Wedge

### 目标用户

- 老师：整理已经上传的课件和视频，让每条视频归属于明确知识点。
- 学生：从课件思维导图进入知识点，并直接观看该知识点下的视频。

### 第一版边界

- 一个视频只能挂载到一个课件的一个知识点。
- 一个知识点可以挂载多个视频。
- 只允许在同一个知识库内挂载。
- 支持现有视频直接挂载，不要求重新上传。
- 支持挂载、改挂、排序、解除挂载和查询。
- 不做视频切片、视频片段与知识点的多对多关联。
- 不修改视频完成规则，继续沿用有效观看达到 90% 的判定。

## Premises

1. 视频继续是独立 `document`，挂载只是新增导航关系，不改变文件存储和观看进度模型。
2. 关联关系不能写进思维导图 JSON，否则思维导图编辑或重新生成可能误删视频关系。
3. 已挂载视频可以从普通资料列表隐藏，但直接访问视频和已有周进度任务仍须正常工作。
4. 删除知识点或课件只解除挂载，不删除视频和观看记录。
5. 删除视频时同步删除挂载关系，再执行现有文档清理流程。
6. 因为该交互尚未经过学生使用验证，未挂载视频必须保留“未归类视频”入口。

## Approaches Considered

### Approach A：使用 `document.meta_fields`

在视频的 JSON 扩展字段中写入 `courseware_doc_id` 和 `knowledge_point_id`。

- Effort: S
- Risk: Medium
- 优点：不增加表，改动小，上线快。
- 缺点：难以查询、排序和约束；知识点删除后容易留下无效关系；后续统计扩展困难。

### Approach B：独立关系表

新增专用表记录视频、课件和知识点之间的关系，视频及其观看记录保持不变。

- Effort: M
- Risk: Low
- 优点：关系清晰，可建立唯一约束和索引；删除与改挂容易保证一致性；便于未来增加必看、顺序和统计。
- 缺点：需要数据库迁移，并同时调整教师端、学生端和清理流程。

### Approach C：写入思维导图节点 JSON

在思维导图每个节点内直接加入 `videos` 数组。

- Effort: S–M
- Risk: High
- 优点：学生读取思维导图时可一次获得全部视频。
- 缺点：内容生成与业务关系耦合；重新生成、审核或删除节点时容易丢失关系；难以维护租户隔离和数据库一致性。

## Recommended Approach

采用 Approach B：独立 `knowledge_point_video_binding` 关系表。

这是唯一能够在不改变既有视频 ID 和学生记录的前提下，稳定支持历史视频挂载、改挂、排序、解除挂载和后续统计的方案。

## Data Model

新增表 `knowledge_point_video_binding`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR(32) | 主键 |
| `video_doc_id` | VARCHAR(32) | 视频文档 ID，唯一 |
| `courseware_doc_id` | VARCHAR(32) | PPT/PDF 等课件文档 ID |
| `knowledge_point_id` | VARCHAR(64) | 思维导图节点 ID |
| `sort_order` | INT | 同一知识点下的视频顺序 |
| `created_by` | VARCHAR(32) | 创建关联的老师 ID |
| 通用时间字段 | BIGINT/DATETIME | 创建与更新时间 |

约束和索引：

- `UNIQUE(video_doc_id)`：保证一个视频只能挂载到一个知识点。
- `INDEX(courseware_doc_id, knowledge_point_id, sort_order)`：支持按节点读取有序视频。
- 不强制数据库外键，保持与现有项目表结构一致；完整性由服务层事务校验。

不修改以下数据：

- `document.id`
- `document.location`
- MinIO 视频对象
- `student_video_progress`
- 周进度中引用的视频 `doc_id`
- 评分系统中引用的视频 `doc_id`

## Backend Rules

### 挂载校验

每次新增或修改挂载时必须验证：

1. 当前老师拥有目标知识库。
2. 视频文档和课件文档真实存在。
3. 两个文档属于同一知识库。
4. 来源文档类型必须是 `video`。
5. 目标文档不能是视频，并且已经解析完成。
6. `knowledge_point_id` 必须存在于目标课件当前思维导图中。
7. 视频已挂载时采用更新关系，不新增第二条关系。

### 建议接口

教师管理端：

- `GET /api/v1/knowledgebases/{kb_id}/video-bindings`
  - 返回知识库内所有视频及其挂载状态。
- `PUT /api/v1/knowledgebases/documents/{video_doc_id}/knowledge-point-binding`
  - 新增或修改挂载，提交 `courseware_doc_id`、`knowledge_point_id`。
- `DELETE /api/v1/knowledgebases/documents/{video_doc_id}/knowledge-point-binding`
  - 解除挂载，不删除视频和观看记录。
- `PUT /api/v1/knowledgebases/documents/{courseware_doc_id}/knowledge-point-videos/order`
  - 更新同一知识点下的视频顺序。

学生端：

- `GET /v1/learning/mindmap/{courseware_doc_id}/videos`
  - 返回学生有权访问的节点视频映射。
  - 每个视频仅返回 `id`、名称、类型、顺序以及当前学生完成状态等必要信息。
  - 视频播放仍使用现有 `/v1/document/get/{video_doc_id}`。
  - 进度查询与上报仍使用现有视频进度接口。

### 清理规则

- 删除知识点：在保存新思维导图的同一事务中，解除所有已不存在节点的挂载。
- 修改知识点名称但保留 `node_id`：挂载保持不变。
- 删除课件：删除以该课件为 `courseware_doc_id` 的关系；视频及进度不删除。
- 删除视频：先删除以该视频为 `video_doc_id` 的关系，再执行原视频清理。
- AI 重新生成思维导图：生成完成后核对节点 ID，不存在的关系自动解除并进入未归类状态。

## Teacher Experience

### 入口一：历史视频快速挂载

在知识库文档列表的视频行增加“挂载知识点”按钮：

1. 点击后打开挂载弹窗。
2. 选择同一知识库中的目标课件。
3. 以可搜索树形选择器展示该课件思维导图。
4. 选择知识点并保存。
5. 已挂载视频显示“课件名称 / 知识点名称”，可改挂或解除。

该入口最适合逐个处理已经上传的历史视频。

### 入口二：按知识点管理视频

在教师“学习内容管理”的思维导图节点旁显示视频数量和“管理视频”：

- 查看该节点已挂载视频。
- 从未归类视频中选择并挂载。
- 调整同一节点的视频顺序。
- 解除挂载。

两个入口复用同一套后端接口和弹窗逻辑。

## Student Experience

1. 学生选择一份 PPT/PDF 课件并打开思维导图。
2. 有视频的知识点显示视频图标和数量，例如“2 个视频”。
3. 点击知识点后，在思维导图弹窗右侧打开知识点详情面板。
4. 详情面板展示有序视频列表、时长和“未开始/学习中/已完成”状态。
5. 点击视频后直接在详情面板播放，不要求先切换顶部文档选择器。
6. 播放器复用原有进度读取、定时上报、续播和 90% 完成判定。
7. 关闭视频后仍停留在当前课件的思维导图位置。

资料列表兼容策略：

- 已挂载视频不再作为普通顶层资料展示，减少列表杂乱。
- 未挂载视频统一放入“未归类视频”分组。
- 从周进度提醒、历史链接或已有地址直接进入视频时，仍可正常播放。

## Rollout Plan

1. 新增关系表与服务层，不改动任何现有视频数据。
2. 增加教师挂载接口和租户/节点校验。
3. 在教师文档列表增加历史视频挂载入口。
4. 在教师思维导图内容管理中增加按节点管理入口。
5. 抽取可复用视频播放器，保证独立视频与知识点视频共用同一进度逻辑。
6. 改造学生思维导图，增加视频标记、详情面板和播放入口。
7. 最后再隐藏已挂载视频的顶层列表入口，避免上线中途学生找不到视频。

上线顺序保证任何阶段都不会阻断现有视频播放。

## Success Criteria

1. 老师可以把任意现有视频直接挂到同知识库的一个知识点，无需重新上传。
2. 挂载前后的 `video_doc_id` 完全一致。
3. 挂载前已有的学生观看秒数、续播位置和完成状态完全一致。
4. 同一个视频无法同时挂载到两个知识点。
5. 学生点击带视频的知识点后，最多两次点击即可开始播放。
6. 嵌入播放产生的进度与原独立视频入口一致。
7. 删除知识点或课件后，视频回到未归类状态，观看记录不丢失。
8. 老师不能跨知识库或跨租户挂载视频。
9. 现有周进度、评分和视频直达链接不受影响。

## Test Plan

- 数据库迁移可重复执行检查。
- 新增、改挂、解除、排序接口测试。
- 视频唯一挂载与同知识库限制测试。
- 非视频作为来源、视频作为目标、无效节点等错误请求测试。
- 租户隔离与学生知识库访问权限测试。
- 历史 `student_video_progress` 挂载前后对比测试。
- 删除知识点、删除课件、删除视频的级联清理测试。
- 学生端节点视频加载、播放、续播和完成状态测试。
- 已挂载/未挂载视频在资料列表中的兼容展示测试。

## Open Questions

推荐默认值如下，可在实现前调整：

- 允许挂载到根节点，用于“课程导学/总览视频”。
- 第一版不要求填写视频说明，直接使用视频文件名。
- 第一版按老师手动排序，不自动按文件名排序。
- 第一版所有挂载视频都视为普通学习材料；“必看/选看”留到后续迭代。

## Dependencies

- 当前思维导图节点 ID 必须在人工编辑时保持稳定；现有教师内容管理已经遵守这一规则。
- 学生端视频播放器逻辑需要抽成可复用组件，防止独立入口和知识点入口出现两套进度实现。
- 文档删除清理服务需要认识新关系表。
- 部署时必须先执行关系表迁移，再发布调用新接口的前端。

## The Assignment

实现前选取一份真实课件、一个知识点和一条已经产生观看记录的视频作为上线验收样本，记录该视频的 `document_id` 以及一名学生当前的观看秒数、续播位置和完成状态。功能上线后用同一组数据验证挂载前后完全一致。

## What I Noticed

需求中最重要的不是“让节点能播放视频”，而是你明确指出历史视频已经有学生观看并产生记录，而且不能重新上传。这把方案从简单的前端嵌套问题变成了数据兼容问题，也直接排除了把视频复制进思维导图内容的做法。独立关系表可以让组织方式改变，而学习事实保持不变。
