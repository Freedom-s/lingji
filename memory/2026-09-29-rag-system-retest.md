# RAG Workflow 线上复测

## 测试范围

- 主机：shiyanshi
- 数据：线上 MySQL 对话配置、线上 Elasticsearch 知识库、线上 MinIO 页面图片
- 对话模型：Qwen3-VL-4B-Instruct
- 流程：意图识别 → 图片/文本/关键词检索 → RRF → Rerank → 前后页页面评估 → 最终生成
- 样本：5 个来自 CH2–CH5 课件的问题
- 负载：预热 1 次；顺序请求 5 次；并发度 2 请求 5 次
- 测试请求不写入线上会话记录

## 工具调用验证

- VLLM 进程已带 `--enable-auto-tool-choice --tool-call-parser qwen3_xml`。
- `tool_choice=auto` 请求返回 HTTP 200，不再出现 400。
- 真实 MinIO 页面图片评估成功。
- Qwen3-VL 返回文本形式 `<tool_call>`，应用层 `chat_with_tools()` 的兜底解析成功转换为工具调用结构。

顺序请求：5/5 成功。

- 首响应：平均 4887.9 ms，P50 4737.0 ms，P95 5350.6 ms，P99 5380.7 ms
- 完整响应：平均 13304.8 ms，P50 13316.8 ms，P95 20997.3 ms，P99 22214.9 ms
- 前后页评估：平均 1042.8 ms
- 检索总耗时：平均 4445.2 ms
- Rerank：平均 2566.8 ms
- 最终生成：平均 8746.1 ms

并发度 2：5/5 成功。

- 首响应：平均 5229.9 ms，P50 4892.5 ms，P95 6902.5 ms，P99 7298.3 ms
- 完整响应：平均 12928.3 ms，P50 11797.7 ms，P95 17695.5 ms，P99 18040.1 ms
- 前后页评估：平均 910.2 ms
- 检索总耗时：平均 4931.4 ms
- Rerank：平均 3179.9 ms
- 最终生成：平均 7867.3 ms

## 结论

- VLLM 工具调用配置已生效。
- 前后页评估链路已恢复，未出现页面评估失败或 `NoneType` 异常。
- 普通 RAG Workflow 在顺序和并发测试中均成功。
- 与此前工具调用失败时相比，前后页评估新增约 0.9–1.0 秒耗时，这是启用页面评估的预期成本；旧基线中的页面评估因 400 错误快速失败，不能直接作为完整链路性能基线。
