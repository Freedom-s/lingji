# 学情分析功能设计文档

## 一、背景与目标

### 1.1 背景

当前系统分为**前台**和**后台**两部分：
- **前台** (`web/` + `api/`)：师生共用，用于 AI 对话和资料浏览
- **后台** (`management/web/` + `management/server/`)：教师专用，用于管理班级/学生/助教/文件和数据概览

学情分析功能应放在**后台管理系统**中，与已有的「数据概览」页面互补。

现有基础设施：
- **班级管理**：后台已有 `/api/v1/teams/*` CRUD API，`class` / `user_class` / `class_dialog` 表已存在
- **数据概览**：后台已有 `/api/v1/dashboard/*` API，返回租户级概览数据（活跃学生、对话趋势、助教排行、班级排行），前端使用 **ECharts** 展示
- **对话数据**：`api_4_conversation` 表记录每次对话的 `user_id`、`dialog_id`、`tokens`、`duration`、`round`、`thumb_up`
- **学生对话查看**：后台已有 `/api/v1/conversation/*` API，可按用户查看对话记录
- **前端技术**：后台使用 Vue 3 + Element Plus + ECharts + Pinia

### 1.2 目标

在**后台管理系统**中为**老师**提供面向班级的学情分析能力，支持多维度数据分析和 AI 驱动的学习洞察。

### 1.3 用户角色

| 角色 | 权限 |
|------|------|
| 老师 (`is_superuser=1`) | 查看自己租户下所有班级的学情数据 |
| 系统管理员 (`is_system=1`) | 同上，外加跨租户查看 |
| 学生 (`is_superuser=0`) | 无后台访问权限 |

### 3.1 学生活跃度

**数据来源**：`conversation` + `api_4_conversation` 表（已有，无需新增表）

**指标列表**：

| 指标 | 计算方式 | 粒度 |
|------|---------|------|
| 对话次数 | `COUNT(conversation.id)` | 班级/学生/天 |
| 提问轮次 | `SUM(api_4_conversation.round)` | 班级/学生/天 |
| 在线时长 | `SUM(api_4_conversation.duration)`（秒） | 班级/学生/天 |
| Token 消耗 | `SUM(api_4_conversation.tokens)` | 班级/学生/天 |
| 最后活跃时间 | `MAX(conversation.create_date)` | 学生 |
| 活跃天数 | `COUNT(DISTINCT DATE(create_date))` | 学生 |
| 周活跃率 | 本周有对话的学生数 / 班级总学生数 | 班级 |

**后端实现**（在 `management/server/` 中）：

```
GET /api/api/v1/analytics/class/:class_id/activity
  参数: from_date, to_date, granularity(day|week|month)
  返回: { pv, uv, rounds, duration, tokens, active_rates }

GET /api/api/v1/analytics/student/:user_id/activity
  参数: from_date, to_date, class_id
  返回: { conversations, rounds, duration, tokens, last_active }
```

**SQL 示例**（班级维度，按天聚合，使用 mysql.connector 原生 SQL）：

```sql
SELECT
    DATE(c.create_date) AS dt,
    COUNT(DISTINCT c.id) AS conversation_count,
    COUNT(DISTINCT c.user_id) AS active_students,
    SUM(a.round) AS total_rounds,
    SUM(a.duration) AS total_duration,
    SUM(a.tokens) AS total_tokens
FROM conversation c
LEFT JOIN api_4_conversation a ON a.user_id = c.user_id
    AND a.dialog_id = c.dialog_id
    AND DATE(a.create_date) = DATE(c.create_date)
INNER JOIN class_dialog cd ON cd.dialog_id = c.dialog_id
WHERE cd.class_id = :class_id
    AND c.create_date BETWEEN :from AND :to
GROUP BY DATE(c.create_date)
ORDER BY dt;
```

### 3.2 对话质量

**数据来源**：`api_4_conversation` 表（已有）

**指标列表**：

| 指标 | 计算方式 | 粒度 |
|------|---------|------|
| 平均对话轮次 | `AVG(round)` | 班级/学生/天 |
| 点赞率 | `SUM(thumb_up) / COUNT(id)` | 班级/学生 |
| 平均回复速度 | `SUM(tokens) / (SUM(duration) + 0.1)`（tokens/秒） | 班级/学生 |
| 对话深度分布 | 按 round 分区统计：1-3轮 / 4-7轮 / 8+轮 | 班级/学生 |
| 问题类型分布 | 基于首条消息做关键词分类（概念解释/习题求解/资料查询等） | 班级 |
| 高频提问主题 | 提取学生消息中的高频词/短语 | 班级 |
| 时段分布 | 按 hour 统计对话发起时间 | 班级 |

**后端实现**：

```
GET /api/api/v1/analytics/class/:class_id/quality
  返回: {
    avg_round, thumb_up_rate, avg_speed,
    depth_distribution: { shallow, medium, deep },
    question_categories: [{name, count}],
    top_keywords: [string],
    hourly_distribution: [{hour, count}]
  }

GET /api/v1/analytics/student/:user_id/quality
  返回: 同上结构，限定单学生
```

### 3.3 课件学习情况（需新增表）

**数据来源**：新增 `learning_behavior` 表

**新增表结构**：

```sql
CREATE TABLE learning_behavior (
    id VARCHAR(32) PRIMARY KEY,
    create_time BIGINT,
    create_date DATETIME,
    user_id VARCHAR(255) NOT NULL,       -- 学生 ID
    class_id VARCHAR(32) NOT NULL,        -- 班级 ID（冗余，方便查询）
    dialog_id VARCHAR(32) NOT NULL,       -- 助教 ID
    doc_id VARCHAR(32) NOT NULL,          -- 课件文档 ID
    page_number INT NOT NULL DEFAULT 0,   -- 当前浏览页码
    action VARCHAR(32) NOT NULL,          -- 'page_view' | 'page_stay' | 'doc_open' | 'doc_close'
    duration INT DEFAULT 0,               -- 停留时长（秒），page_stay 时有效
    INDEX idx_user_date (user_id, create_date),
    INDEX idx_class_date (class_id, create_date),
    INDEX idx_doc (doc_id)
);
```

**埋点时机**：在 `/learning` 页面中：

| 事件 | 触发时机 | 上报频率 |
|------|---------|---------|
| `doc_open` | 学生选择课件文档时 | 即时 |
| `page_view` | 切换到新页面时 | 即时 |
| `page_stay` | 离开当前页面/关闭文档时 | 记录在上一页停留的时长 |
| `doc_close` | 关闭课件选择（clear）时 | 即时 |

**指标列表**：

| 指标 | 计算方式 |
|------|---------|
| 课件打开次数 | `COUNT(DISTINCT doc_id)` per student |
| 已浏览页数 | `COUNT(DISTINCT page_number)` per doc per student |
| 课件完成率 | `已浏览页数 / 课件总页数` per student |
| 页面停留时长 | `SUM(duration)` per page / per doc / per student |
| 热门页面 | `COUNT(page_view) GROUP BY page_number` per doc |
| 学生课件学习时长趋势 | 按天统计 `SUM(duration)` |

**后端实现**：

```
POST /api/v1/analytics/behavior
  请求体: { doc_id, page_number, action, duration }
  说明: 前端自动上报，用于写入 learning_behavior 表

GET /api/v1/analytics/class/:class_id/courseware
  返回: {
    doc_engagement: [{ doc_name, open_count, avg_progress, total_duration }],
    student_progress: [{ user_id, nickname, doc_name, viewed_pages, total_pages, progress }],
    hot_pages: [{ doc_name, page_number, view_count }],
    daily_duration: [{ date, total_duration }]
  }

GET /api/v1/analytics/student/:user_id/courseware
  返回: {
    doc_views: [{ doc_name, first_open, last_open, viewed_pages, total_pages, total_duration }],
    page_details: [{ doc_name, page_number, duration, view_count }]
  }
```

### 3.4 知识点掌握度（AI 驱动，需新增表 + LLM）

**数据来源**：新增 `knowledge_assessment` 表 + LLM 分析

**新增表结构**：

```sql
CREATE TABLE knowledge_assessment (
    id VARCHAR(32) PRIMARY KEY,
    create_time BIGINT,
    create_date DATETIME,
    class_id VARCHAR(32) NOT NULL,
    student_id VARCHAR(255) NOT NULL,
    dialog_id VARCHAR(32) NOT NULL,
    conversation_id VARCHAR(32) NOT NULL,
    knowledge_point VARCHAR(255) NOT NULL,  -- 知识点名称
    mastery_level VARCHAR(16) NOT NULL,      -- 'high' | 'medium' | 'low' | 'unknown'
    confidence FLOAT DEFAULT 0.0,            -- AI 判断置信度
    evidence TEXT,                            -- AI 给出的判断依据
    assessed_by VARCHAR(32) DEFAULT 'llm',   -- 'llm' | 'teacher' | 'self'
    INDEX idx_student (student_id),
    INDEX idx_class_kp (class_id, knowledge_point)
);
```

**分析流程**：

```
┌──────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────────────┐
│ 学生对话  │───▶│ 提取知识点     │───▶│ LLM 掌握度   │───▶│ knowledge_        │
│ 历史记录  │    │ (LLM 分析)    │    │ 评级         │    │ assessment 表     │
└──────────┘    └──────────────┘    └─────────────┘    └──────────────────┘
```

1. **提取知识点**：LLM 分析学生的对话历史，识别涉及的知识点名称（如 "状态空间搜索"、"逆否命题"）
2. **掌握度评级**：LLM 根据对话质量（提问深度、理解程度、纠错次数）给出评级：
   - `high`：能举一反三，提出深入问题
   - `medium`：基本理解，有少量疑问
   - `low`：频繁提问基础概念，理解有偏差
   - `unknown`：证据不足，无法判断
3. **定时分析**：每天凌晨对新增对话做一次分析（通过 cron 任务），可选择是否手动触发

**可视化方案**：

| 展示 | 形式 | 说明 |
|------|------|------|
| 班级知识掌握热力图 | 热力矩阵（学生 × 知识点 × 颜色深浅） | 一眼看出薄弱环节 |
| 单个学生知识图谱 | 雷达图 | 多维度能力评估 |
| 班级薄弱知识点 Top N | 柱状图 | 按 `low` 占比排序 |
| 知识掌握趋势 | 折线图 | 同一知识点在不同时期的变化 |

**后端实现**：

```
POST /api/v1/analytics/class/:class_id/assess
  说明: 触发 LLM 分析（异步任务），分析该班级下所有学生的对话
  返回: { task_id }

GET /api/v1/analytics/class/:class_id/knowledge
  返回: {
    heatmap: [{ student_name, knowledge_point, level }],
    weak_points: [{ knowledge_point, low_count, total_count, low_rate }],
    summary: "班级整体掌握情况文字描述..."  (LLM 生成)
  }

GET /api/v1/analytics/student/:user_id/knowledge
  返回: {
    assessments: [{ knowledge_point, level, confidence, evidence }],
    radar: [{ knowledge_point, score(0-100) }],
    trend: [{ date, knowledge_point, level }]
  }
```

## 七、数据安全与性能

### 7.1 权限控制

- 老师只能查看自己租户下的班级数据
- 使用后台已有的 `@require_superuser` 装饰器保护所有学情 API
- 按租户隔离：所有 SQL 查询通过 `tenant_id` 过滤

### 7.2 性能考虑

| 场景 | 方案 |
|------|------|
| 大班级长时间范围查询 | 对 `create_date`、`class_id`、`user_id` 添加索引 |
| LLM 分析耗时 | 异步任务（Redis Queue），返回 task_id 轮询 |
| 前端大数据量展示 | 后端分页（学生列表）、前端虚拟滚动 |
| 缓存 | 对聚合统计数据做 Redis 缓存（TTL: 1小时） |

### 7.3 索引建议

```sql
-- conversation 表
CREATE INDEX idx_conv_user_date ON conversation(user_id, create_date);
CREATE INDEX idx_conv_dialog_date ON conversation(dialog_id, create_date);

-- api_4_conversation 表
CREATE INDEX idx_api4_user_date ON api_4_conversation(user_id, create_date);
CREATE INDEX idx_api4_dialog_date ON api_4_conversation(dialog_id, create_date);

-- learning_behavior 表（已在建表语句中包含）
-- knowledge_assessment 表（已在建表语句中包含）
```
