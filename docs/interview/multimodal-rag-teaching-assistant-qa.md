# 多模态 RAG 课程智能助教：完整面试答稿

> 用法：先练项目总述和案例，再按问题练“判断依据 → 方案 → 代价 → 验证”。文中的“当前”依据 2026-10-14 的仓库代码；“下一步”“我会”是可讨论的设计方案。模型训练、离线数据集规模和线上用户量需要用你的实验记录补齐，不能从代码推断。

## 一、开场介绍

### 90 秒项目介绍

“这个项目是面向高校实验课程的智能助教平台。课件里有文字、公式、示意图和跨页步骤，纯文本检索容易漏掉图像信息，通用模型又不能保证回答基于本校课件。我主要围绕两个问题做设计：一是如何在页级找到正确证据，二是如何让答疑与学生学习过程衔接。

检索侧把课件按页面组织，建立图像向量、文本向量和关键词三路索引；在线链路并行召回、RRF 融合、Reranker 重排，再由 VLM 评估是否需要相邻页，最后基于页面图文回答并返回引用。学生侧已经记录测验、闪卡、笔记和知识点掌握状态，支持复习计划与教师学情查看。

目前主对话仍以固定答疑链路为主，ReAct/MCP Agent 是已搭建但默认关闭的原型。下一阶段我想把结构化学情接入 Agent：课程资料决定事实，学生记忆决定讲解策略。这能让系统从一次性答疑，走向跨会话的诊断、讲解、练习和复习闭环。效果上我会同时看检索 Recall、答案依据性、延迟，以及学生后续作答改善，而不是只看模型回答是否流畅。”

### 一张口述架构图

```text
教师课件 → 页级解析/截图 → 图像向量、文本向量、BM25 → ES
学生提问 → 登录与课程权限 → 三路召回 → RRF → Reranker → 相邻页判断
         → 课件页面图文 → VLM 回答与页级引用 → 会话存储
学生测验/闪卡/笔记 → MySQL 知识点掌握状态 → 学情反馈
                                       └→ [规划] 学生记忆装配 → 个性化答疑
```

### 一个贯穿全场的案例

“学生问：‘这张图里的反馈回路为什么要加负号？’系统先确定其班级与可访问课件，再并行检索图像、OCR 文本和关键词。图像路能看到回路结构，文本路找到公式说明，BM25 命中‘负反馈’。融合和重排后，若关键推导在下一页，就补齐相邻页。VLM 根据两页证据解释符号来源，并给页码。未来若该学生在相关知识点测验中连续答错，系统会增加一步前置解释或诊断题；这条学习记录影响教学方式，不改变课件事实。”

## 二、逐题回答

### 业务与产品定位

#### 1. 请用一个学生问题讲完整链路

“我会用上面的负反馈问题讲。教师课件入库时生成页图、文本和索引；学生提问时先完成身份与课程范围校验，再检索、重排、补页、生成、引用，最终把问答存入会话。测验与笔记形成另一条学习数据链，教师可以看到班级层面的薄弱知识点。关键是让每一步都有可观察的输入输出，错误时能判断是解析、召回、重排还是生成出了问题。”

#### 2. 为什么学生不用通用大模型？

“课程问题通常要求按指定教材、实验步骤和教师术语回答。通用模型可能给出普遍正确、但与这门课要求不一致的解释。平台的价值是把答案约束在学生有权限访问的课件范围，提供页级出处，并和测验及复习状态衔接。对于课件没有的内容，我会明确标记其来源或说明未找到，避免把外部知识伪装成教师材料。”

#### 3. 最核心指标是什么？

“如果只选一个最终指标，我选学生在相同知识点的后续作答改善，因为产品目标是学会，而不是当场觉得回答好。工程上仍需分层看：检索 Recall 与引用正确率诊断证据链，答案正确率诊断生成，延迟和成本保证可用性。学生满意度是辅助信号，不能代替学习效果。”

#### 4. 只给两周，先改哪里？

“先用真实失败问题做归因，再决定。若正确页面没进候选集，改召回；若页面已召回却答错，改重排、上下文组装或答案约束。就当前系统而言，我会优先建立覆盖图表、公式、跨页的回归集和链路 trace，因为它能让之后每项优化都有证据，而不是凭几次演示选方向。”

#### 5. 你个人最关键的设计决策是什么？

“我会重点讲页级多模态证据链：把页作为检索、读图和引用的统一对象，再把不同模态的候选融合起来。这个决策牺牲了比小文本块更细的定位，却保留了图表布局和实验步骤的完整性。另一种方案是纯文本切块，我会拿图表题和跨页题的失败案例说明为什么没有只采用它。”

### 多模态检索

#### 6. 一页 PPT 有文字、公式和流程图，如何表示？

“我会把一个稳定的 `page_id` 作为主键，同时保存页图、抽取文本、页码、文档版本和课程归属，并分别建立图像向量、文本向量、关键词索引。页级对象便于直接给 VLM 看原始布局，也便于引用。代价是单页可能信息过多，所以可在页内保留区域坐标做精定位，但最终仍回到同一页证据。”

#### 7. 跨页答案先补页还是先重排？

“默认先召回与重排主页面，再对高分页做相邻页判断，以免对几十张候选页都扩展，导致成本和噪声上升。若测试集显示实验步骤经常跨页而主页面召回不足，可以在粗排阶段加入轻量的相邻页扩展。两种顺序用跨页题的完整证据召回率、平均读图页数和延迟比较。”

#### 8. 三路分数不同，‘概率融合’如何做？

“当前在线实现用 RRF，只融合各路名次，避免直接相加不同量纲的分数。若升级为概率融合，我会在按课程与文档隔离的验证集上，把各路原始分数校准成‘该页相关’的概率，再按题型或可学习权重融合，并检查校准误差与 Recall。不能把 sigmoid 一套就叫概率，也不能用测试集调权重。面试时我会清楚区分在线 RRF 与实验中的概率方案。”

#### 9. 同一页被多路命中怎么去重？

“按 `page_id` 聚合候选，保留三路的排名和原始分数作为解释字段，融合后只让该页进入一次重排。这样既避免重复占用 top-k，也能分析某类题由哪条召回路贡献。若课件重入库导致 `page_id` 变化，还要结合文档版本和页面内容指纹处理逻辑重复。”

#### 10. 口语描述流程图与精确公式名如何处理？

“两者不应强迫走同一路。口语化图形问题通常更依赖图像语义，精确术语更依赖 BM25；三路并行能保证基础召回。进一步可做轻量题型识别，用于动态调整候选配额，但要保留其他路的最低配额，防止路由误判直接丢掉正确页。”

#### 11. 外观相似、参数不同的截图如何区分？

“图像向量负责粗召回，关键参数需要 OCR、表格结构或元数据核验。Reranker 应比较问题中的参数与候选页的实际数值；生成阶段也要让模型指出使用的是哪张图、哪个参数。评测集中专门放‘视觉相似但参数不同’的困难负例，不能只看普通 Recall。”

#### 12. 课件更新后旧引用如何处理？

“索引与引用都携带 `doc_version`。新版本构建完成后原子切换可检索版本，旧会话仍能显示原版本及‘资料已更新’提示。若旧版需要删除，就在引用处标注失效，并提供新版本的候选对应页；不要悄悄把旧页码指向新内容。”

#### 13. 只找到一半答案怎么办？

“先分解问题，明确哪一部分已有课件依据、哪一部分缺失；对缺失部分可再检索一次或查相邻页，达到预算上限后停止。若允许联网，应把网络来源与课件来源分开呈现；若不允许，就只回答有依据的部分并说明缺口。停止条件要写在代码预算与产品策略中，不能完全依赖模型‘觉得够了’。”

### 微调与实验

#### 14. 为什么微调 Embedding？

“先建立强基线：解析质量、BM25、原始 Embedding、查询改写和 Reranker。若错误集中在领域术语、课件图像与口语问题的跨模态匹配，才有理由训练 Embedding。微调的价值应体现为固定下游流程时 Recall 上升，同时检查训练成本、索引重建成本和跨课程泛化。”

#### 15. 两阶段 LoRA 分别解决什么？

“可以将第一阶段设计为课程领域的图文语义对齐，让学生提问与相关课件页靠近；第二阶段加入困难负样本和排序信号，拉开相似页面。顺序的理由是先学稳定的语义空间，再处理精细边界。实际答辩时要拿出每阶段数据、损失函数、冻结参数和消融结果；没有这些证据就只说设计，不说已证实。”

#### 16. 困难负样本如何挖，如何避开假负例？

“先用现有检索器找高分但标注不相关的候选，重点覆盖相邻章节、相似图形和同名术语。候选负例需人工抽查或用课程知识结构校验；同一知识点的另一张正确页不能直接当负例。训练时可给不确定负例较低权重，并维护误标回收机制。”

#### 17. Reranker 蒸馏怎么讲？

“教师模型对‘问题、候选页’给软相关分数，学生模型学习排序和分数差异；训练要覆盖真阳性、近似错页和随机负例。核心收益应是用更低推理成本保住重排质量。具体教师和学生 checkpoint、标签来源、蒸馏损失与加速比必须按实验记录回答；这四项不能用通用方案冒充已完成工作。”

#### 18. 自建数据如何防泄漏？

“按文档或课程划分训练、验证和测试，避免同一 PPT 相邻页分别出现在训练与测试中。问题改写、同一答案的多个表述也要一起分组。外部数据集严格沿用公开划分，并记录是否经过领域训练。最后人工审查一批最高增益样本，排除题目措辞直接泄漏页标题。”

#### 19. Recall@5 三个提升数字怎么解释？

“我会先给出每个数据集的样本数、正例定义、相同的候选库、基线配置与评测脚本版本，再说明 2.16、13.89、5.17 是百分点。还会给出分题型表现和置信区间，避免平均数掩盖退化。现在简历只写了提升幅度，面试前必须从原始实验表补齐基线绝对值、样本数和消融配置。”

#### 20. Recall 上升而答案正确率没升怎么办？

“先看正确页是否进入最终 VLM 上下文，而不只是 top-5；再看重排是否把它排低、上下文是否过长、截图是否清晰，以及生成是否错误理解图形。用逐环节 oracle 实验定位：给生成器人工正确页，如果仍答错就是读图或生成问题；给重排器固定正确候选，如果仍漏选就是重排问题。”

#### 21. 新 Embedding 上线如何迁移索引？

“新旧向量不能默认混用。我会建立新版本索引，在后台全量编码，增量同步课件变更；用影子流量比较质量和延迟，达到门槛后切换读别名。回滚时读别名指回旧索引，确认稳定后再清理旧数据。文档版本和模型版本都进入索引元数据，便于排查混索引问题。”

### Agent 与固定答疑链路

#### 22. 固定 Pipeline 已能答疑，为什么还需要 Agent？

“固定链路适合大多数课件问答，因为路径可预测、成本和结果容易控制。Agent 用于不确定任务，例如学生问‘对比第三章两份实验报告中标定步骤的差异，并解释我的测验错因’，系统可能需要先查文档列表、分别检索、补页，再读取学情。我的策略是固定链路作为默认，复杂任务经轻量判定进入有边界的 Agent。当前 Agent 代码是原型且默认关闭，生产效果需要单独评测。”

#### 23. 哪些由模型决定，哪些必须由代码决定？

“模型可以决定检索词、是否补查和如何组织解释；代码决定用户身份、课程范围、工具 schema 校验、超时、调用次数和可访问资源。身份与权限不能作为 Prompt 中的建议，更不能让模型自己填写。教学策略如是否给作业完整答案，也应由教师配置和服务端规则约束。”

#### 24. MCP 工具空结果、超时、格式错误如何恢复？

“空结果允许有限次查询改写或拆题；超时可做一次有上限重试，之后降级到已取得的证据；格式错误先由服务端 schema 校验并返回结构化错误。每种失败要记录工具名、参数摘要、耗时和错误类型。向学生解释能回答的部分与无法确认的部分，不把堆栈信息直接输出。”

#### 25. Agent 重复调用相同工具如何终止？

“对规范化后的工具名和参数计算 action key，连续重复且结果没有新增证据时累加无进展计数。达到阈值后提示模型改写策略或终止；另有硬性的最大调用数与总时长。终止时返回已验证的信息与缺口，而不是再让模型无限自我纠正。”

#### 26. 最大工具数、token、时间怎么设？

“这些是产品预算，应从线上延迟与任务复杂度分布反推，不能凭空给一个通用值。可以给简单问答更小预算、跨文档问题更大预算，并设置单工具超时、总 token 和总时长三个独立上限。触发上限后优先保住有依据的部分答案，标明未完成步骤；记录触发率用于调参。”

#### 27. 模型能自己指定学生和课程 ID 吗？

“不能。API 从已认证会话拿 `student_id`，查班级成员关系与 Dialog 绑定的知识库，再把允许的范围作为服务端上下文传给工具。模型只提供与任务有关的查询词等业务参数。即使工具收到 `tenant_id` 或 `kb_ids`，服务端也要再次校验其与当前身份一致，防止绕过上游。”

#### 28. 工具轨迹要展示给谁？

“学生只需要看到‘查了哪些课件、引用了哪些页、为什么暂时不能回答’，原始工具 JSON 会增加阅读负担，也可能暴露内部信息。教师可查看课程层面的失败类型与资料缺口；开发人员需要完整 trace、模型版本、工具耗时与脱敏参数。三种视图共用 trace ID，但权限和数据保留期不同。”

#### 29. 相同问题不同学生得到不同答案，合理吗？

“先拆开事实层与教学层：引用的课程结论应一致，例子、讲解顺序与提示深度可以因学情不同。回归测试固定课件版本和模型版本，比较关键事实、引用页与结论；个性化差异另用策略测试验证。若不同学生得到相反的公式或实验步骤，就属于错误而不是个性化。”

### 学生记忆

#### 30. 到底记住什么？问过等于不会吗？

“我把记忆分为会话上下文、结构化学情和少量跨会话偏好。单次提问只表示关注，不等于不会；错误作答也可能是粗心。掌握度应依据多次客观作答和复习轨迹，保留证据来源与时间。对话中提取的‘可能误解’只作为待验证线索，不能直接覆盖测验记录。”

#### 31. 各类记忆保存多久？

“当前会话按 token 预算保留并可摘要，课程学情通常覆盖一个教学周期，明确讲解偏好可以跨课程但允许随时修改。低置信度的临时困惑设置较短失效期；原始对话与派生摘要遵循产品的数据保留政策，支持删除。时间策略还要区分‘数据保存期’与‘对当前回答的有效期’。”

#### 32. 答错一次就标薄弱吗？

“不会。我会把一次错误作为事件写入，而知识点状态结合题目难度、最近正确率、复习间隔和证据量计算。低证据时可安排一道诊断题，避免过度个性化。当前代码已有按知识点记录正确/错误次数和复习时间的基础；下一步需完善证据权重及状态置信度。”

#### 33. 旧偏好与当前指令冲突怎么办？

“当前明确指令优先决定这次回答的形式。例如平时喜欢简短回答，但这次要求详细推导，就详细讲。长期偏好只作为缺省值，并在响应后根据明确反馈更新；不能把‘今天想看详细版’自动改成永久偏好。”

#### 34. 学生说‘我已经学会了’，直接改掌握状态吗？

“这是一条自我报告，应该尊重，但与客观掌握证据不同。系统可停止重复讲解，给一道小诊断题；答对后再更新掌握度和复习计划。这样既不和学生争辩，也不因为一句话抹掉连续错误记录。”

#### 35. 记忆字段怎么设计？

“最小记录包括 `tenant_id、class_id、student_id、doc_id、node_id、memory_type、value、source_type、source_id、confidence、observed_at、expires_at、version`。`source_id` 让它能追溯到测验、笔记或会话；版本与时间解决课件更新和新旧冲突。结构化掌握度留在 MySQL，语义片段量大时才另建向量索引。读取端始终按身份、课程和版本过滤。”

#### 36. ‘接着讲上次那道题’怎么找？

“先在当前课程范围内按最近会话、题目引用页与知识点找候选，若只有一个高置信候选就继续；多个候选时给学生列出简短选项确认。不能用全站语义检索随意挑一题，更不能把其他班级的同名题目带进来。确认结果可以更新当前会话指代，但不必写成长期偏好。”

#### 37. 所有聊天都要向量化吗？

“不需要。测验结果、掌握度、复习时间和最近会话可以用主键及时间索引确定性读取；只有‘上次讨论过某种思路’之类难以结构化的经历，才有语义检索价值。即使建立向量索引，也只索引筛选后的摘要和来源 ID，而不是无差别复制原始聊天。”

#### 38. 两门课都有‘梯度下降’怎么办？

“先由班级、Dialog、课件版本确定本次课程范围，再查课程内的知识点节点和学情。跨课程复用可以作为显式的‘先修知识’能力，但要通过知识点映射和权限校验，而不是凭名称相同合并两条掌握记录。输出中应能说明使用的是哪门课的资料。”

#### 39. 学生笔记写错公式怎么办？

“笔记是学生学习状态的证据，不是课程知识的权威来源。检索到笔记后，系统应对照课件或教师材料核验；若冲突，温和地指出差异并给页级引用。原笔记不能在未告知学生的情况下被改写，最多提供修订建议与确认操作。”

#### 40. 学生删除历史后如何清理？

“以来源 ID 建立派生关系。删除会话时，清理相应的原文、摘要、向量项和缓存；对已汇总进掌握度的证据，按产品规则决定重算或撤销。删除过程采用可重试任务与审计记录，向用户显示完成状态。向量库与缓存的清理失败不能静默忽略。”

#### 41. 如何证明记忆真的有效？

“先构建跨会话测试集：同一个学生在前一轮留下错误证据，下一轮问相关问题，检查系统是否召回正确记忆、有没有误用他人记忆、解释是否适配。线上更关注同知识点的后续正确率、复习完成率和学习时长。对照组使用相同检索与生成链路，只关闭记忆，避免把模型升级收益算给记忆。”

### 教学闭环

#### 42. 基础薄弱与已掌握学生怎么区别回答？

“课程结论与引用页一致；薄弱学生先解释前置概念、分步推导并给一个检查问题，已掌握学生直接讲关键差异和拓展。差异依据是近期作答与知识点状态，而非年龄、学校等无关属性。回答后要通过小测或追问验证这种策略确实改善理解。”

#### 43. 学生索要实验作业答案怎么办？

“教师配置作业模式：可先提示实验目标、指出课件页、检查学生已有步骤，再逐步增加提示。对开放的复习题可以直接给完整解答；对正在评分的作业，默认不生成可直接提交的成品。策略由课程与任务状态确定，Agent 负责在允许范围内表达，不能自行突破。”

#### 44. 如何识别卡在先修概念？

“将课件知识点组织为有向先修关系，记录题目与节点的对应。学生当前题答错时，先看直接先修点的近期表现；若同一先修点在多题中持续出错，就先补基础。知识图的边由教师审核或从课程结构产生候选，不能让模型凭一次聊天随意建立教学依赖。”

#### 45. 学生说看懂了但测验一直错？

“先分析错因是否一致：概念定义、图形识别、计算步骤或审题。若是表征问题，换图示或实例；若是前置知识问题，回溯先修点；若仍不清楚，就出一道区分性诊断题。系统不应机械地重复同一段更长的解释。”

#### 46. 主动提醒怎样避免打扰？

“提醒由到期复习、课程进度和学生设置共同决定，设置每日上限、静默时段和关闭入口。排序优先‘即将需要且有证据表明薄弱’的知识点，不是所有到期卡片都推送。评测除完成率外，还看关闭率、忽略率与后续学习效果。”

#### 47. 全班都在某页提问，说明什么？

“可能是课件表达不清，也可能是解析或检索把无关问题都导向该页。教师视图应把提问聚类、引用页、测验错误率和检索置信度放在一起看。若问题多且测验也错，优先优化教学内容；若检索置信度低且引用分散，优先排查索引与召回。”

#### 48. 教师更新课件后如何映射掌握记录？

“知识点 ID 应尽量独立于页码；新版课件先通过教师确认的映射关系连接旧、新节点。完全相同的概念可沿用历史证据，拆分或合并的节点要降低置信度并安排重新验证。旧测验记录保留原版本，避免把旧题的正确率直接解释成新版内容已掌握。”

### 工程、权限与成本

#### 49. 考前并发增长十倍，谁先成为瓶颈？

“先用 trace 和压测而不是猜。页级图像的 VLM 推理、重排与 MinIO 读取通常都值得单独测；ES 查询、数据库连接池和图片转换也可能先饱和。分段测吞吐、P95、队列等待和错误率，然后用限流、缓存、批处理或服务扩容处理实际瓶颈。缓存不能跨权限边界复用个性化结果。”

#### 50. 缓存哪些结果，缓存键怎么定？

“课件解析、无用户差异的页面检索结果可以按 `tenant、kb、doc_version、query_normalized、model_version` 缓存；学生画像和最终回答要包含学生与课程范围，且 TTL 更短。资料更新时按版本自然失效。即使缓存命中，返回前仍做当前权限校验，避免某学生退出班级后继续读到旧缓存。”

#### 51. 流式回答中途失败怎么办？

“把一次响应视为有状态执行：`started → streaming → completed/failed`。流式事件携带 trace ID 和序号，前端能区分暂存片段与最终答案；数据库只把完整、验证过的响应标为完成。失败时保留可诊断状态和已确认引用，重试使用幂等请求 ID，避免同一个学生问题被写入两次。”

#### 52. 先优化平均耗时还是 P95？

“先看用户体验和分布。如果大多数请求快、少数图像问题超过等待阈值，优先 P95；如果所有请求都慢，优先平均耗时。trace 拆成三路召回、融合、重排、取图、VLM 评估、答案生成，找出耗时与正确率的共同拐点，避免为提速删掉真正有用的证据。”

#### 53. 教师能看到多少学生记忆？

“教师默认看课程内的学习汇总和教学所需的个人掌握状态；学生私人对话和偏好不应自动全量开放。具体权限分为学生自查、任课教师、管理员，并按班级和课程归属执行后端校验，记录敏感读取审计。产品上允许学生查看和更正被系统归纳的学习信息。”

#### 54. 课件里藏有恶意指令怎么办？

“课件与网页是数据，不是系统指令。工具权限和课程范围由服务端限定；生成时将检索内容以带来源的引用数据传入，避免它改变工具调用规则。对‘忽略之前指令、泄露数据’等文本建立回归样本，检查模型输出与工具轨迹；涉及写操作的工具还需要服务端审批或禁用。”

### 评测与产品决策

#### 55. 怎样同时评估找页、答题、引用和教学？

“分四层。第一层是页面证据 Recall@k、MRR 与跨页完整率；第二层是答案事实正确率和拒答准确率；第三层是引用是否真正支持对应句子；第四层是学生后测与延迟复测的正确率。数据集按文字、公式、图表、跨页、无答案及对抗样本分桶，报告总体和分桶结果。只有第一层提升而第四层不变，说明系统优化没有转化为学习收益。”

#### 56. 记忆 A/B 实验怎么设计？

“按学生或班级随机，而不是按单次问题随机，避免同一个学生在两组之间带入历史学习效应。保持课件、检索模型和生成策略一致，实验组只多记忆装配；按课程、教师、基础水平分层。预先确定主指标和观察周期，监控隐私误用与跨用户泄漏这种不能只看平均值的错误。”

#### 57. ‘有帮助’能直接当训练标签吗？

“不能。学生可能因为答案短、语气好而点赞，即使课件引用错误；也可能因为被要求自己思考而点踩一个教学上更有效的提示。反馈要与引用正确性、测验后测和人工抽检结合。若用于训练，需去重、识别群体偏差，并保留一组不受反馈闭环影响的固定评测集。”

#### 58. 个性化成本高且学习效果无提升怎么办？

“保留证据明确、成本低的结构化能力，例如到期复习提示与知识点掌握状态；暂停大范围语义记忆召回和复杂生成策略。再分组看是否只对基础薄弱学生或某类题有效，决定精确投放。若仍无改善，就不应为了‘智能化’名义保留高成本链路。”

#### 59. 教师、学生、开发人员标准不一，以谁为准？

“先定义不可妥协的底线：事实与引用正确、权限不泄漏。教学目标由课程教师与产品目标共同确定，学生反馈用于衡量可理解性和体验，工程指标保证稳定运行。冲突时公开指标的优先级，例如学生喜欢直接答案，但教师要求对在评分的作业先给提示，就按课程策略执行。”

### 压力追问

#### 60. 你的 Agent 独特性在哪？规则加 RAG 会差多少？

“我不会预设 Agent 必然更好。独特性应来自动态处理不确定任务：识别需查哪份课件、何时补相邻页、何时用学情调整讲解，并在预算内停止。是否值得上线要用固定 Pipeline、规则增强 Pipeline、Agent 三组比较答案质量、时延、成本和失败率。若 Agent 增益不覆盖复杂度，就把它限制在少数复杂问题。”

#### 61. 把全部历史塞进 Prompt 不就有记忆了吗？

“上下文长度、成本和噪声会随历史增长；更重要的是原始聊天混合了已证实测验、随口猜测和过时偏好。记忆系统要做筛选、归因、更新、删除和权限控制，按当前问题只取相关且有来源的信息。完整历史仍可存档，但不应每次无差别交给模型。”

#### 62. 既有掌握度数据库，为什么还要 LLM 提取记忆？

“客观学情由数据库和规则负责，不需要 LLM 重算。LLM 只适合处理难结构化的对话线索，例如学生反复混淆两个概念，但抽取结果必须有原句来源、置信度与人工或后续测验验证。第一版甚至可以只用结构化学情，不上对话抽取；这是成本和可靠性更好的起点。”

#### 63. 错误解释却引用了正确页面，如何复盘？

“引用正确只说明找到了页，不代表模型读懂。保留问题、候选页、重排分、传给 VLM 的图像、最终回答与版本信息，复盘时先固定输入重放。若人工能从同一页答对而模型答错，改读图、提示或换模型；若该页本身不支持那句话，则改引用校验。把该案例加入回归集，确认修复没有伤害其他图表题。”

#### 64. 预算砍半，四项能力保留哪两项？

“我会先保留高质量的多模态检索与可验证的固定答疑链路，因为它们构成课程助教的基本可信度；若选项必须在‘微调、多模态检索、Agent、学生记忆’中二选一，我先保留多模态检索和结构化学生记忆。微调可以等待明确的召回瓶颈，通用 Agent 可以按需试点。选择依据是分层实验的增益/成本比，而不是技术热度。”

#### 65. 你离开后团队怎样继续迭代？

“交付三类资产：一张标明权限边界与数据流的架构图，一套可复现的评测集及配置版本，一份按 trace 定位失败的运行手册。模型、索引和 Prompt 都版本化；每次变更记录基线、预期收益、回滚条件。这样团队能基于证据继续实验，而不是依赖我口头解释某个参数为什么设成 0.7。”

## 三、面试中可以主动抛出的设计判断

1. **事实与教学策略分层。** 课程课件决定知识事实，学生记忆决定解释顺序与深度；事实结论不能因学生不同而相反。
2. **先做可验证的结构化记忆。** 已有知识点掌握、测验和复习时间，可以先接入 Agent；聊天摘要与语义记忆在证据不足时会引入误判。
3. **固定链路作为默认，Agent 处理不确定任务。** 这样能把动态规划的收益和额外成本量化，而不是给每个问题都跑多轮工具。
4. **每项模型优化都要有下游价值。** Recall 增益要追踪到最终答案、引用和学习效果，且同时报告成本、延迟与失败样本。
5. **学生记忆要能纠错和删除。** 任何‘学生不会某知识点’的判断都带来源、时间和置信度，并允许新证据推翻。

## 四、面试前必须填好的个人证据表

| 主题 | 需要准备的真实材料 |
| --- | --- |
| 三组 Recall@5 提升 | 每组基线绝对值、改进后绝对值、样本数、正例定义、评测脚本、置信区间或重复实验 |
| 两阶段 LoRA | 数据构造、模型 checkpoint、训练目标、关键超参、每阶段消融和失败样本 |
| Reranker 蒸馏 | 教师与学生模型、软标签来源、损失函数、排序指标、推理延迟 |
| 线上使用 | 部署范围、实际课程与用户量、问题量、稳定性；没有统计就不要口述估计值 |
| 检索链路 | 一例图表题、一例跨页题、一例失败题，附候选排序和最终引用 |
| 学生记忆 | 明确说现有结构化学情与未来 Agent 记忆接入的边界，准备一条跨会话案例 |

## 五、与当前代码保持一致的口径

- 在线主答疑检索使用**图像向量、文本向量、BM25 三路召回 → RRF 融合 → Reranker → 阈值处理 → 相邻页补全**。如果概率融合是另一版实验，应称为“实验方案”，并准备该实验的代码与结果。
- 主对话入口的 Agent 开关目前为 `False`。可以介绍 ReAct/MCP 原型与下一步的 Agent 化设计，不要把它描述成当前所有线上请求都在运行的链路。
- 学生测验、闪卡、笔记和知识点掌握状态已经存储；**Agent 尚未把这些状态装配进对话上下文**。这是学生记忆方向最自然的扩展点。
- 当前阈值处理在全部候选低于阈值时仍会保留最高分页面。若面试中谈“无依据时拒答”，应说是计划加入的答案依据校验，不要声称已由该阈值保证。
